    UT1 · Guía de estudio de Bash¶

    Esta página es una guía de repaso para estudiar la UT1. No sustituye los apartados detallados: los ordena, destaca lo que conviene dominar y utiliza ejemplos cortos.

    1. Estructura mínima de un script¶

    #!/bin/bash
echo "Hola mundo"

    chmod +x script.sh
./script.sh
# o bien
bash script.sh

    #!/bin/bash indica el intérprete. Para ejecutar con ./script.sh hace falta permiso de ejecución.

    2. Variables, comillas y entrada¶

    nombre="Jose"
echo "Hola $nombre"
read -r -p "Nombre del usuario: " usuario
echo "Usuario: $usuario"

    Error típico

    nombre = "Jose" es incorrecto. En una asignación no hay espacios alrededor de =.

    Regla práctica: cuando pasas una variable a una orden, normalmente usa "$variable" para conservar espacios.

    Variables de entorno que conviene reconocer: $HOME, $USER, $PATH, $PWD, $SHELL, $HOSTNAME.

    3. Parámetros¶

    Si ejecutas:

    ./alta.sh pepe 25

    Dentro del script:

    echo "$0"  # nombre del script
echo "$1"  # pepe
echo "$2"  # 25
echo "$#"  # número de parámetros
echo "$@"  # todos los parámetros

    Validación típica:

    if (( $# != 2 )); then
    echo "Uso: $0 usuario edad" >&2
    exit 1
fi

    4. Arrays¶

    servidores=("web01" "db01" "backup01")
echo "${servidores[0]}"
echo "${servidores[@]}"
echo "${#servidores[@]}"

    Recorrerlos:

    for servidor in "${servidores[@]}"; do
    echo "$servidor"
done

    5. Matemáticas¶

    Para enteros, la forma recomendada es $(( ... )) o (( ... )):

    usados=70
total=100
libres=$((total - usados))
echo "$libres"

    Para decimales, el material utiliza bc:

    resultado=$(echo "scale=2; 10 / 3" | bc)
echo "$resultado"

    6. Tests: archivos, cadenas y números¶

    Archivos¶

    [[ -e "$ruta" ]]  # existe
[[ -f "$ruta" ]]  # archivo regular
[[ -d "$ruta" ]]  # directorio
[[ -r "$ruta" ]]  # legible
[[ -w "$ruta" ]]  # escritura
[[ -x "$ruta" ]]  # ejecutable
[[ -s "$ruta" ]]  # tamaño > 0

    Cadenas¶

    [[ -z "$nombre" ]]       # vacía
[[ -n "$nombre" ]]       # no vacía
[[ "$a" == "$b" ]]      # iguales
[[ "$a" != "$b" ]]      # diferentes

    Números¶

    Operador Significado
    -eq igual
    -ne diferente
    -lt menor
    -le menor o igual
    -gt mayor
    -ge mayor o igual 
    if [[ $ocupacion -ge 90 ]]; then
    echo "Alerta"
fi

    Con [[ ... ]] puedes combinar condiciones con && y ||.

    7. Manipulación de cadenas¶

    archivo="informe_final.pdf"
echo "${archivo:0:7}"  # informe
echo "${archivo%.*}"   # informe_final
echo "${archivo##*.}"  # pdf
echo "${#archivo}"     # longitud

    Estas expansiones son muy útiles para tratar nombres de archivos sin invocar herramientas externas.

    8. if, elif, else¶

    if [[ $nota -ge 9 ]]; then
    echo "Excelente"
elif [[ $nota -ge 5 ]]; then
    echo "Aprobado"
else
    echo "Suspenso"
fi

    Piensa siempre: ¿qué condición quiero comprobar y qué ocurre en cada caso?

    case "$1" in
    iniciar)
        echo "Iniciando"
        ;;
    parar)
        echo "Parando"
        ;;
    *)
        echo "Opción desconocida"
        ;;
esac

    10. Bucles¶

    for¶

    for usuario in ana juan pedro; do
    echo "$usuario"
done

    for ((i=1; i<=5; i++)); do
    echo "$i"
done

    while¶

    contador=1
while [[ $contador -le 5 ]]; do
    echo "$contador"
    ((contador++))
done

    until¶

    Se repite hasta que la condición es cierta:

    contador=1
until [[ $contador -gt 5 ]]; do
    echo "$contador"
    ((contador++))
done

    continue salta a la siguiente iteración; break sale del bucle.

    11. Funciones¶

    comprobar_usuario() {
    if id "$1" &>/dev/null; then
        return 0
    fi
    return 1
}

if comprobar_usuario "alumno"; then
    echo "Existe"
else
    echo "No existe"
fi

    Una función debe definirse antes de utilizarla. Sus argumentos también son $1, $2... return devuelve un código de salida, no una cadena.

    Para obtener un valor:

    sumar() {
    echo $(($1 + $2))
}

resultado=$(sumar 4 6)

    12. grep y expresiones regulares¶

    Patrones básicos:

    Patrón Significado
    ^ inicio de línea
    $ final de línea
    . cualquier carácter
    [0-9] un dígito
    [A-Z] una mayúscula
    [^0-9] cualquier carácter que no sea un dígito

    Con grep -E tienes regex extendidas: +, ?, {n}, {n,m}, | y ( ).

    grep '^root' /etc/passwd
grep 'bash$' /etc/passwd
grep -E 'error|fallo' sistema.log
grep -E '^[0-9]{4}$' codigos.txt

    En Bash puedes validar directamente con =~:

    if [[ $puerto =~ ^[0-9]{1,5}$ ]]; then
    echo "Formato numérico correcto"
fi

    13. Herramientas de texto que debes saber combinar¶

    grep -i "error" sistema.log
cut -d: -f1 /etc/passwd
awk -F: '{print $1, $3}' /etc/passwd
sort nombres.txt
sort nombres.txt | uniq -c
tr '[:lower:]' '[:upper:]' < nombres.txt
find . -type f -name "*.log"

    cut funciona bien con un delimitador claro. awk es mejor cuando quieres trabajar con columnas y condiciones.

    14. sed¶

    sed 's/http/https/' config.txt
sed 's/http/https/g' config.txt
sed '/error/d' log.txt
sed '/^$/d' archivo.txt
sed -n '3,7p' archivo.txt

    -i modifica el archivo real:

    sed -i.bak 's/antiguo/nuevo/g' config.txt

    Esto crea una copia .bak antes de modificar.

    15. Pipes y redirecciones¶

    ps -ef | grep ssh
comando > archivo.txt
comando >> archivo.txt
comando 2> errores.log
comando &> todo.log

    > sustituye; >> añade. La pipe | envía la salida de una orden a la entrada de la siguiente.

    16. Errores y depuración¶

    Todo comando devuelve un código: 0 = éxito, otro valor = error.

    ls /etc/passwd
echo "$?"

    Para depurar:

    bash -x script.sh

    Otras herramientas del tema:

    set -e
set -u
trap 'echo "Interrumpido"; exit 1' SIGINT SIGTERM

    17. Ejemplo integrador¶

    Script que recibe un directorio y cuenta los .log:

    #!/bin/bash

if (( $# != 1 )); then
    echo "Uso: $0 directorio" >&2
    exit 1
fi

ruta=$1

if [[ ! -d "$ruta" ]]; then
    echo "El directorio no existe" >&2
    exit 2
fi

cantidad=$(find "$ruta" -type f -name '*.log' | wc -l)
echo "Archivos .log: $cantidad"

    Aquí combinas parámetros, if, test de directorio, sustitución de comandos, find, pipe y wc.

    UT1 · 1. Bash: scripts, variables, entrada y parámetros¶

    ¿Qué ejecuta Bash?¶

    Una shell interpreta comandos. Un script guarda comandos en un archivo para que puedas repetir el proceso. La primera línea #!/bin/bash indica que el script se ejecuta con Bash, situado en /bin/bash, como utilizamos en clase. Con bash nombre.sh eliges Bash explícitamente; con ./nombre.sh necesitas permiso de ejecución, que puedes dar con chmod u+x nombre.sh.

    En Bash, nombre=valor asigna y $nombre expande el valor. No pongas espacios alrededor de =. Las comillas dobles conservan los espacios de un dato, pero expanden variables; las simples tratan el contenido literalmente. Los comentarios comienzan con #.

    De una orden a un script: qué cambia realmente¶

    Cuando escribes una orden en el terminal, Bash la interpreta en ese momento. Al guardar varias órdenes en un archivo no inventas un lenguaje distinto: preparas una secuencia para repetirla. El archivo no se ejecuta solo por terminar en .sh. Puedes entregárselo a Bash con bash ficha.sh; para ejecutarlo como ./ficha.sh necesita tanto una cabecera de intérprete correcta como permiso de ejecución.

    Puedes crear ficha.sh en un editor de texto, escribir la primera línea #!/bin/bash y guardar. bash ficha.sh inicia Bash y le entrega el archivo. chmod u+x ficha.sh permite después invocarlo como ./ficha.sh. El ./ significa «búscalo en esta carpeta»: la carpeta actual no tiene por qué estar en PATH.

    Si estás en otra carpeta, bash ficha.sh no busca el archivo junto al que tienes abierto en el editor. Parte del directorio de trabajo. Compruébalo con pwd y utiliza una ruta relativa o absoluta que corresponda. Esta distinción evita confundir un problema de localización con un error del código.

    Asignar, leer y delimitar una variable¶

    Una variable permite dar un nombre a una información. Al asignar no se escribe $; al utilizar el valor se expande con $. Bash no necesita que declares de antemano que será texto o un número para estos casos sencillos.

    nombre="Carpeta de láminas"
echo "$nombre"
base="lamina"
echo "${base}_revisada.txt"

    La salida es:

    Carpeta de láminas
lamina_revisada.txt

    echo muestra un texto y añade un salto de línea. La primera orden lee el valor de nombre; la segunda une el valor de base con _revisada.txt. Las llaves delimitan dónde acaba el nombre: $base_revisada buscaría una variable llamada base_revisada, no uniría automáticamente el valor de base con ese sufijo.

    Los nombres distinguen mayúsculas: nombre y Nombre no son la misma variable. Pueden contener letras, cifras y guiones bajos, pero no empezar por cifra. Usa nombres que expliquen el dato y evita ocupar nombres del sistema para otros fines.

    Mostrar texto con echo¶

    echo muestra lo que recibe y añade un salto de línea. Las comillas dobles permiten incluir el valor de una variable dentro del mensaje:

    nombre="Láminas grandes"
echo "Nombre: $nombre"

    La salida es Nombre: Láminas grandes. Nombre: es texto fijo y $nombre se sustituye por el valor guardado. Para mostrar dos líneas, escribe dos órdenes echo; no necesitas introducir códigos de formato.

    Por qué las comillas cambian los argumentos¶

    Bash prepara los argumentos antes de llamar a una orden. Si expandes una variable sin comillas en una orden corriente, el resultado puede dividirse en palabras y tratar caracteres como * como patrones de nombres. Las comillas dobles mantienen el resultado como un argumento y permiten expandir variables. Las simples conservan el texto literalmente.

    nombre="Láminas   grandes"
echo "$nombre"
echo $nombre
echo 'El contenido de $nombre no se expande aquí'

    La primera orden conserva los tres espacios del valor. En la segunda, Bash lo divide en dos argumentos y echo los muestra separados por un espacio. La tercera conserva literalmente los caracteres $nombre.

    Láminas   grandes
Láminas grandes
El contenido de $nombre no se expande aquí

    Aunque las dos primeras líneas se parecen, Bash no ha entregado los mismos argumentos. Esto importa cuando otra orden espera recibir un único nombre con espacios.

    Este efecto importa al copiar, buscar o imprimir nombres con espacios. La regla práctica para pasar un dato como argumento es "$variable". No añadas comillas al azar a toda la sintaxis: una expresión regular o un patrón pueden necesitar que parte de su sintaxis conserve su significado.

    Capturar la salida no es capturar el estado¶

    resultado=$(orden) ejecuta una orden y captura su stdout, eliminando los saltos de línea finales. No captura automáticamente stderr. El código de salida sigue siendo otra información distinta, que puedes comprobar con un if o guardar inmediatamente.

    fecha=$(date +%Y-%m-%d)
echo "Fecha del informe: $fecha"

    El valor de la fecha depende del día del equipo. No esperes el texto date +%Y-%m-%d: las comillas y $() indican operaciones distintas. Una variable normal tampoco se convierte en una variable de entorno hasta que la exportas; una shell hija recibe el entorno exportado, no todos los nombres internos de su padre.

    Qué significa recibir varios argumentos¶

    En bash ficha.sh "Sala azul" 3, la shell entrega dos argumentos. Dentro del script, $1 es Sala azul, $2 es 3 y $# es 2. "$@" permite reenviar cada argumento manteniendo sus límites; "$*" los reúne en un solo texto separado normalmente por espacios.

    Comprueba primero cuántos argumentos hay. Que una variable tenga texto no demuestra que exista el número correcto de argumentos: alguien puede pasar una cadena vacía explícita. ${1:-general} utiliza general si el primer argumento no existe o está vacío; ${1-general} solo lo hace cuando no existe.

    shift retira el primer argumento posicional y desplaza los demás. Es útil cuando el primero indica una acción y el resto son sus datos. Antes de usarlo, comprueba que hay algo que retirar. No modifica la lista de argumentos de otra llamada independiente ni borra variables con nombres propios que ya hayas creado.

    Problema explicado paso a paso: etiqueta de una muestra de laboratorio¶

    Guarda etiqueta.sh:

    #!/bin/bash
if (( $# != 2 )); then
    echo 'Uso: bash etiqueta.sh muestra responsable' >&2
    exit 1
fi
muestra=$1
responsable=$2
read -r -p 'Ubicación de la muestra: ' ubicacion
echo "Muestra: $muestra"
echo "Responsable: $responsable"
echo "Ubicación: $ubicacion"

    Ejecuta bash etiqueta.sh "Roca volcánica" "Laia Ferrer" y escribe Armario azul.

    Resultado esperado: tres líneas con la muestra, el nombre completo y la ubicación. Las comillas hacen que cada frase sea un argumento. Sin ellas, el número de argumentos cambiaría y el script mostraría la ayuda.

    Paso a paso¶

    1. $# cuenta argumentos. Si no son dos, el mensaje va a la salida de error con >&2 y el código final es 1.
    2. $1 y $2 son los datos de la llamada. $0 es el nombre con el que se ha invocado el script.
    3. read -r lee una línea sin tratar las barras invertidas como escapes.
    4. Cada echo muestra una línea con su etiqueta y la variable correspondiente. Las comillas mantienen los espacios de los valores.

    Variables que conviene reconocer¶

    Expresión Significado
    "$@" Todos los argumentos, conservando cada uno
    $? Código del último comando, que cambia al ejecutar el siguiente
    $$ Identificador del proceso de la shell
    ${nombre:-alternativa} Alternativa si no existe o está vacío
    $(comando) Captura la salida estándar del comando

    Una variable de shell no pasa necesariamente a los procesos hijos. export COLOR_FICHA=azul la incorpora al entorno de los nuevos procesos. printenv COLOR_FICHA la consulta. Utiliza nombres propios del script: no sobrescribas PATH con una ruta de trabajo, porque dejarías de localizar comandos.

    Transformar texto y guardar colecciones¶

    #!/bin/bash
archivo='muestra.version.txt'
echo "${archivo%.txt}"
echo "${archivo:0:7}"
salas=('Sala azul cielo' 'Sala gris')
echo "${salas[0]}"
echo "${#salas[@]}"

    El primer bloque muestra muestra.version y muestra. % elimina el sufijo que coincide con el patrón; ${texto#patron} elimina un prefijo; las versiones dobles %% y ## eliminan la coincidencia más larga. ${texto:inicio:longitud} extrae una subcadena. Los arrays indexados comienzan en cero y "${salas[@]}" conserva cada elemento.

    Error Solución
    nombre = valor Escribe nombre=valor.
    Un nombre con espacios se divide Utiliza "$nombre" al pasarlo a un comando.
    Argumentos vacíos o desplazados Revisa las comillas en la llamada y $#.

    Elegir entre argumentos y entrada interactiva¶

    Si el enunciado dice «recibe una carpeta», la interfaz normal es bash programa.sh carpeta. Si dice «pregunta la carpeta», utiliza read. Un script programado sin una persona delante no debería quedarse esperando una respuesta por teclado.

    Variante de read Cuándo utilizarla
    IFS= read -r linea Conservar espacios iniciales y barras invertidas
    read -r -s clave No mostrar lo que se escribe; añade después un salto de línea
    read -r -t 10 respuesta Esperar como máximo diez segundos y comprobar su estado
    read -r nombre resto Repartir una línea entre varias variables

    Problema explicado paso a paso: conservar nombres con espacios en un array¶

    #!/bin/bash
salas=('Azul cielo' 'Gris perla')
salas+=('Verde musgo')
for indice in "${!salas[@]}"; do
    echo "$indice: ${salas[$indice]}"
done

    La salida tiene tres líneas: 0: Azul cielo, 1: Gris perla y 2: Verde musgo. += añade sin sustituir lo anterior; ${!salas[@]} recorre los índices existentes. Las comillas conservan cada nombre completo. unset 'salas[1]' eliminaría ese elemento, pero no renumeraría automáticamente los demás.

    Para cargar un archivo de una entrada por línea, utiliza mapfile -t salas < salas.txt en una versión de Bash que disponga de mapfile. Es más seguro para espacios que salas=($(cat salas.txt)). Los arrays asociativos necesitan declare -A y permiten acceder por clave, como capacidad[azul]=18.

    Ejercicios para practicar¶

    Intenta resolverlos antes de abrir la solución. Puedes consultar la teoría; después repite alguno sin mirar para comprobar qué recuerdas. Las pistas y soluciones están cerradas para que elijas cuándo verlas.

    1. Conserva cada argumento¶

    Escribe argumentos.sh para mostrar cuántos argumentos recibe y después imprimir cada uno entre < y >, en su propia línea. Prueba bash argumentos.sh azul "gris claro". No utilices read.

    Pista

    $# cuenta argumentos y "$@" conserva sus límites.

    Solución paso a paso 
    #!/bin/bash
echo "Argumentos: $#"
for argumento in "$@"; do
    echo "<$argumento>"
done

    La salida es Argumentos: 2, <azul> y <gris claro>. Las comillas de la llamada agrupan el segundo argumento. El for recorre "$@" y conserva cada argumento completo. Si no pasas ninguno, solo aparece Argumentos: 0: el bucle no imprime un elemento vacío.

    2. Genera un nombre sin tocar archivos¶

    Recibe como único argumento un nombre terminado en .csv. Supón que el sufijo es correcto. Quita ese sufijo y construye el nombre acabado en _revisado.csv. Imprime el resultado sin crear ni renombrar ningún archivo. Prueba con lista del club.csv.

    Pista

    Puedes quitar el sufijo con ${nombre%.csv} y delimitar la variable al añadir texto.

    Solución paso a paso 
    #!/bin/bash
if (( $# != 1 )); then
    echo 'Uso: bash nombre.sh archivo.csv' >&2
    exit 1
fi
nombre=$1
base=${nombre%.csv}
echo "${base}_revisado.csv"

    El resultado es lista del club_revisado.csv. Primero validamos el número de argumentos; después transformamos texto. No hay ninguna operación de escritura sobre el sistema de archivos.

    3. Añade y consulta una colección¶

    Crea un array con lunes y martes, añade jueves y cambia el segundo elemento por miércoles. Muestra solo el último elemento y el número de elementos. No copies manualmente toda la lista otra vez.

    Pista

    Los índices empiezan en cero. Añadir utiliza += y cambiar un elemento utiliza su índice.

    Solución paso a paso 
    #!/bin/bash
dias=(lunes martes)
dias+=(jueves)
dias[1]='miércoles'
echo "Último: ${dias[2]}"
echo "Cantidad: ${#dias[@]}"

    La salida es Último: jueves y Cantidad: 3. Cambiar una posición no aumenta el tamaño; añadir un elemento sí.

    UT1 · 2. Cálculos, comprobaciones y decisiones en Bash¶

    Tres tipos de comprobación¶

    Para enteros, (( expresion )) permite calcular y comparar. Para texto y archivos, [[ condicion ]] resulta cómodo en Bash. La forma clásica [ condicion ] también existe y exige espacios alrededor de los corchetes y operandos bien separados.

    Necesidad Expresión de Bash
    Archivo ordinario [[ -f "$ruta" ]]
    Directorio [[ -d "$ruta" ]]
    Existe una entrada [[ -e "$ruta" ]]
    Enlace simbólico [[ -L "$ruta" ]]
    Texto vacío / no vacío [[ -z "$texto" ]] / [[ -n "$texto" ]]
    Texto igual [[ "$texto" == "abierto" ]]
    Entero de al menos 3 (( cantidad >= 3 ))

    -e puede ser falso en un enlace roto: utiliza también -L si quieres detectar cualquier enlace. && significa «y», || significa «o» y ! niega una condición. Un comando con código 0 se considera correcto o verdadero en un if.

    Hacer cuentas: no todo texto parecido a una operación se calcula¶

    Si escribes echo '8 + 3', estás imprimiendo texto. La expansión aritmética $((8 + 3)) pide a Bash que evalúe la operación y sustituya la expresión por su resultado.

    piezas=23
capacidad=5
completos=$((piezas / capacidad))
sobrantes=$((piezas % capacidad))
echo "Lotes completos: $completos; piezas sueltas: $sobrantes"

    Resultado: Lotes completos: 4; piezas sueltas: 3. La división entera cuenta cuántos grupos completos caben; el resto cuenta lo que queda. No son resultados intercambiables. Si necesitas incluir un grupo incompleto, necesitas decidir qué hacer con el resto.

    Las multiplicaciones y divisiones respetan la prioridad habitual; los paréntesis aclaran el orden. Al calcular un porcentaje entero, dividir demasiado pronto puede perder la fracción: con 3 de 8 piezas, 3 / 8 * 100 da 0, mientras 3 * 100 / 8 da 37. Este último valor sigue siendo una aproximación entera, no 37,5.

    Dentro de ((...)) puedes utilizar el nombre de la variable sin $. Es un contexto aritmético, no una cadena normal. No introduzcas datos sin validar en él: la shell puede interpretarlos como expresiones y no como la cantidad literal que imaginabas.

    Cómo decide if: estado cero significa verdadero¶

    La estructura se lee «ejecuta esta prueba; si termina con estado cero, ejecuta este bloque»:

    if [[ 3 -gt 2 ]]; then
    echo 'La condición se cumple'
else
    echo 'La condición no se cumple'
fi

    El ejemplo imprime «La condición se cumple» porque 3 es mayor que 2. then inicia el primer camino y fi cierra la estructura. else es opcional. El sangrado de los bloques facilita la lectura, pero Bash reconoce los límites por sus palabras de control, no por el número de espacios.

    [ ... ] es una orden de prueba que exige argumentos separados: [ "$a" -gt 3 ] contiene espacios después de [ y antes de ]. [[ ... ]] es una construcción propia de Bash, con reglas más cómodas para patrones y condiciones compuestas. Para números, ((...)) admite comparaciones como >=.

    No utilices un > suelto como si fuera una comparación numérica dentro de [ ... ]: la shell puede tratarlo como redirección. Los operadores numéricos clásicos son -eq, -ne, -lt, -le, -gt y -ge; los de texto son = y !=.

    Elegir el orden de varias condiciones¶

    Un if/elif/else ejecuta el primer camino verdadero. Ese orden forma parte de la solución. Si primero preguntas «¿hay al menos una pieza?», una cantidad de veinte también cumple; nunca llegaría a un elif posterior pensado para cantidades grandes.

    Define intervalos de manera que cubran los casos válidos sin dejar huecos. Prueba exactamente los valores de frontera, no solo valores intermedios. Un programa que distingue menos de 5, de 5 a 10 y más de 10 debe probar 4, 5, 10 y 11, además de una entrada inválida.

    Al combinar condiciones, A && B exige ambas y A || B admite al menos una. El cortocircuito evita evaluar lo que ya no hace falta. Puedes aprovecharlo para validar antes de calcular: primero el texto debe tener la forma permitida y solo después haces la comparación numérica.

    Verificar una ruta es hacer una pregunta concreta¶

    -e pregunta si existe, -f si es un archivo ordinario y -d si es un directorio. Una carpeta puede existir y aun así no ser un archivo de entrada válido. -r, -w y -x preguntan por accesos, mientras -s pregunta si tiene tamaño no nulo.

    Si una operación falla, responde a la pregunta que realmente necesitabas comprobar. Por ejemplo, antes de leer un documento puedes exigir que sea archivo ordinario y legible; no necesitas hacerlo ejecutable. Sobre un directorio, x significa poder atravesarlo, no que sea un programa.

    Problema explicado paso a paso: comprobar una reserva de butacas¶

    Una sala de prueba tiene 12 butacas libres. El script acepta una cantidad entre 1 y 12, escrita con una o dos cifras sin ceros iniciales.

    #!/bin/bash
peticion=${1:-}
if [[ ! "$peticion" =~ ^[1-9][0-9]?$ ]]; then
    echo 'Escribe una cantidad de una o dos cifras, sin cero inicial.' >&2
    exit 1
fi
libres=12
if (( peticion > libres )); then
    echo 'No hay suficientes butacas.'
elif (( peticion == libres )); then
    echo 'La sala queda completa.'
else
    quedan=$((libres - peticion))
    echo "Reserva aceptada. Quedan $quedan butacas."
fi

    Sigue tres entradas¶

    Llamada Condición Salida esperada
    bash butacas.sh 5 5 < 12 Quedan 7 butacas
    bash butacas.sh 12 12 = 12 Sala completa
    bash butacas.sh 13 13 > 12 No hay suficientes butacas
    bash butacas.sh cinco No cumple el patrón Mensaje de entrada incorrecta

    La validación se hace antes de la aritmética. ^ y $ anclan todo el texto; [1-9] es la primera cifra y [0-9]? permite una segunda opcional. El patrón sin comillas a la derecha de =~ es una expresión regular, no texto literal.

    Aritmética y opciones de menú¶

    $((7 / 2)) devuelve 3: la aritmética ordinaria de Bash es entera. % calcula el resto. Para decimales puedes utilizar bc, si está instalado:

    echo 'scale=2; 7 / 2' | bc

    Resultado: 3.50. scale controla los decimales en la división; no es una regla universal de redondeo monetario. expr y let aparecen en scripts antiguos, pero $((...)) suele ser más legible.

    Para opciones concretas, case evita cadenas largas de igualdades:

    accion=${1:-ayuda}
case "$accion" in
    resumen) echo 'Muestra el resumen de la sala' ;;
    ayuda) echo 'Opciones: resumen, ayuda' ;;
    *) echo 'Opción desconocida' >&2; exit 1 ;;
esac

    Usar directamente el resultado de un comando¶

    Una condición de shell también puede ser un comando: no necesitas capturar su texto y compararlo si ya proporciona un estado útil.

    #!/bin/bash
if command -v bash >/dev/null 2>&1; then
    echo 'Bash está disponible'
else
    echo 'No se ha localizado Bash en PATH' >&2
fi

    command -v comprueba si puede localizar el comando. >/dev/null 2>&1 descarta su salida y sus errores; el if sigue recibiendo el código de salida. En un sistema donde ejecutas este script con Bash, el resultado normal es el primer mensaje.

    Las formas cortas orden && siguiente y orden || alternativa dependen del mismo mecanismo: la segunda orden se ejecuta si la primera termina bien o mal, respectivamente. No sustituyas automáticamente un if/else por a && b || c: si b falla, también se ejecuta c.

    Comparaciones que suelen confundirse¶

    Expresión Qué pregunta
    [ "$a" = "$b" ] ¿Son iguales como texto?
    [ "$a" -eq "$b" ] ¿Son iguales como enteros?
    [[ -r "$ruta" ]] ¿Se puede leer la ruta?
    [[ -x "$ruta" ]] ¿Tiene acceso de ejecución o búsqueda para este usuario?
    [[ "$nombre" == *.txt ]] ¿Coincide con un patrón de nombre?
    [[ "$nombre" =~ ^[A-Z]+$ ]] ¿Coincide con esta expresión regular?

    En la prueba de patrón *.txt, dejar el patrón sin comillas permite interpretarlo como patrón; la variable sigue protegida. Diferencia este caso de pasar argumentos a una orden externa, donde normalmente debes entrecomillar las expansiones.

    UT1 · 3. Bucles y funciones: repetir sin duplicar¶

    ¿Cuándo conviene cada bucle?¶

    for recorre una colección conocida. while repite mientras una condición es verdadera. until repite mientras es falsa. break sale del bucle y continue pasa a la siguiente vuelta. En todos los casos debes poder explicar la condición de finalización.

    Construir un bucle a partir de su condición de parada¶

    Un bucle ahorra repetir instrucciones, pero también obliga a definir cómo avanza el trabajo. Antes del código, escribe tres cosas: qué valor tiene el estado inicial, qué se hace en una vuelta y qué cambio acerca el programa al final.

    En un for sobre una lista, la propia lista limita las vueltas. En un while, tú debes cambiar algún dato o recibir una nueva entrada que pueda volver falsa la condición. En un until, el cuerpo se repite hasta que la condición pasa a ser verdadera. No es una instrucción que espere mágicamente a que el sistema cambie por sí solo.

    paso=1
while (( paso <= 3 )); do
    echo "Preparación $paso"
    paso=$((paso + 1))
done
echo "Valor al terminar: $paso"

    La salida enumera preparaciones 1, 2 y 3, y termina mostrando 4. La cuarta comprobación se hace, pero el cuerpo ya no se ejecuta. Esta diferencia entre comprobar y ejecutar explica muchos errores de una vuelta de más o de menos.

    Un contador se inicia antes del bucle si debe conservar el progreso. Si vuelves a poner paso=1 dentro del cuerpo en cada vuelta, lo reinicias y puedes impedir que llegue a la parada.

    Distinguir detener la búsqueda de omitir un elemento¶

    continue salta el resto del cuerpo y pasa a la siguiente vuelta. break termina el bucle más cercano. En bucles anidados no termina automáticamente toda la aplicación.

    Piensa en revisar una lista de carpetas: una entrada no válida puede omitirse con continue; encontrar el elemento exacto que buscabas puede justificar break. Si usas break para saltar una entrada incorrecta, abandonarías todas las que todavía faltan por revisar.

    Al anidar recorridos, el número de vueltas se multiplica. Tres zonas y cuatro turnos generan doce combinaciones. Escribe qué representa cada variable y evita reutilizar el mismo nombre para las dos, porque perderías el significado del recorrido exterior.

    Crear una función y llamarla son dos acciones distintas¶

    La definición nombre() { ...; } enseña a Bash una orden reutilizable. El cuerpo no se ejecuta por aparecer en el archivo: lo ejecutas escribiendo nombre argumentos, sin paréntesis en la llamada.

    Los parámetros posicionales se refieren a la llamada actual. Dentro de etiqueta "Azul", $1 significa Azul, aunque el script haya recibido antes otros argumentos. Si necesitas entregar un argumento del script a una función, debes pasárselo explícitamente.

    mostrar_ficha() {
    local titulo=$1
    local zona=${2:-sin_asignar}
    echo "Ficha: $titulo; zona: $zona"
}
mostrar_ficha 'Mapa antiguo' 'Sala azul'
mostrar_ficha 'Plano pequeño'

    La primera llamada muestra ambos datos. La segunda utiliza sin_asignar porque no recibe un segundo argumento. local evita sustituir por accidente variables del mismo nombre en el código que llama a la función.

    Datos y estado: dos canales para dos preguntas¶

    Una función puede producir un texto y además indicar si pudo completar su tarea. Los datos se escriben por stdout; el estado se devuelve con return. Quien llama puede capturar los primeros y comprobar el segundo.

    formar_codigo() {
    if [[ ! "$1" =~ ^[A-Z]{2}$ ]]; then
        echo 'Se necesitan dos letras mayúsculas' >&2
        return 1
    fi
    echo "FICHA-$1"
}
if codigo=$(formar_codigo 'AZ'); then
    echo "Código recibido: $codigo"
fi

    El resultado es Código recibido: FICHA-AZ. Si pruebas con Az, la función escribe un error por stderr y el if no entra. Capturar stdout no implica que la operación haya ido bien; por eso se comprueba el estado.

    Si añades mensajes de depuración por stdout, también acabarán dentro de codigo. Mantén ahí solo el dato que has prometido devolver y utiliza stderr para diagnóstico. Esta separación permite reutilizar una función sin tener que limpiar su salida cada vez.

    Problema explicado paso a paso: preparar etiquetas de estanterías¶

    Queremos cuatro etiquetas, excepto la tercera, que está fuera de servicio. Una función crea cada etiqueta para que el formato esté en un único lugar.

    #!/bin/bash
etiqueta() {
    local numero=$1
    echo "ESTANTERIA-0$numero"
}
for numero in 1 2 3 4; do
    if (( numero == 3 )); then
        continue
    fi
    etiqueta "$numero"
done

    Salida esperada: ESTANTERIA-01, ESTANTERIA-02 y ESTANTERIA-04, cada una en una línea.

    1. La función se define antes de llamarla.
    2. Dentro de la función, $1 es el primer argumento de la función, no necesariamente el del script.
    3. local limita la variable a la función. Para los números del 1 al 4 de este ejemplo, 0$numero construye las etiquetas 01 a 04. No es una regla general para números de cualquier longitud.
    4. continue omite la etiqueta 3, pero permite que el recorrido continúe con 4.

    while y until con seguimiento¶

    #!/bin/bash
pendientes=3
while (( pendientes > 0 )); do
    echo "Cajas pendientes: $pendientes"
    pendientes=$((pendientes - 1))
done

revisadas=0
until (( revisadas == 2 )); do
    revisadas=$((revisadas + 1))
    echo "Revisión $revisadas completada"
done

    El while muestra 3, 2 y 1. El until muestra las revisiones 1 y 2: cuando la condición pasa a ser verdadera, ya no entra. Cambiar until por while sin negar la condición altera completamente el comportamiento.

    Función que calcula y función que comprueba¶

    Bash distingue datos por stdout y estado por return:

    #!/bin/bash
nombre_etiqueta() {
    echo "CAJA-$1"
}
es_codigo() {
    [[ "$1" =~ ^[A-Z]{2}[0-9]{2}$ ]]
}
nombre=$(nombre_etiqueta 'AB42')
if es_codigo 'AB42'; then
    echo "$nombre es válido"
fi

    $(...) captura el texto. La función de comprobación devuelve el estado del último comando: 0 si el patrón coincide. return 250 es un código de estado, no una forma de devolver un texto ni un cálculo arbitrario.

    Si separas funciones en un archivo propio, source ./funciones.sh las carga en la shell actual; ejecutar bash funciones.sh inicia una shell hija y no deja las definiciones disponibles en la shell que la llamó.

    Error Causa y corrección
    Bucle infinito No cambia la variable que decide la parada.
    El valor capturado contiene mensajes sobrantes La función imprime depuración por stdout; envíala a stderr.
    return truncado Los estados tienen un rango limitado; utiliza stdout para los datos.

    Leer un archivo línea a línea sin romper sus datos¶

    Este patrón de los apuntes anteriores es útil para procesar listados. Mantiene espacios, barras y la última línea aunque no termine con salto:

    #!/bin/bash
while IFS= read -r linea || [[ -n "$linea" ]]; do
    echo "Recibido: [$linea]"
done < notas.txt

    Para probarlo, crea notas.txt con dos líneas: Sala azul y Pendiente de revisar. Obtendrás una línea Recibido: [...] por cada una. IFS= evita recortar o separar por espacios; -r conserva las barras; < notas.txt conecta el archivo con la entrada del bucle.

    En Bash, un bucle colocado después de una tubería suele ejecutarse en una subshell. Si cuentas dentro de cat notas.txt | while ..., el contador puede no conservar su valor fuera del bucle. La redirección anterior evita esa dificultad.

    Menú que se repite hasta terminar¶

    #!/bin/bash
while true; do
    read -r -p 'Escribe ver o salir: ' opcion || break
    case "$opcion" in
        ver) echo 'La consulta está preparada' ;;
        salir) break ;;
        *) echo 'Opción no reconocida' ;;
    esac
done

    Con las entradas ver, otra y salir, se muestran el mensaje de consulta y el aviso de opción incorrecta; la tercera termina el bucle. La comprobación de read también permite salir si se cierra la entrada. Si quieres un menú numerado, select lo genera; REPLY contiene la respuesta escrita y la variable elegida contiene el texto de la opción.

    UT1 · 4. Archivos, tuberías, filtros y expresiones regulares¶

    Conectar comandos¶

    Un comando dispone de entrada estándar, salida estándar y salida de error. > crea o sobrescribe; >> añade; 2> redirige errores; | envía stdout a la entrada del siguiente comando. El error no entra automáticamente en la tubería.

    grep selecciona líneas, cut extrae campos, sort ordena, uniq agrupa repeticiones consecutivas y wc cuenta. awk trabaja bien con campos y sed con transformaciones de texto. find busca entradas del sistema de archivos según nombre, tipo u otras propiedades.

    Pensar una tubería como transformaciones de datos¶

    La tubería conecta programas; no sabe lo que significa una fila ni corrige datos incoherentes. Antes de unir órdenes, escribe cómo es la entrada y qué debería salir de cada tramo. Si un filtro elimina todas las líneas por error, las órdenes siguientes solo procesarán una entrada vacía.

    grep filtra por contenido, cut selecciona campos por delimitador, sort ordena y uniq agrupa líneas consecutivas iguales. wc -l cuenta saltos de línea. Son tareas pequeñas que se combinan; intercambiar el orden puede cambiar el resultado.

    Si el campo contiene una cantidad, sort -n ordena numéricamente. Sin -n, la comparación textual puede colocar 10 antes que 2. Esto no es un fallo del programa: has pedido otro criterio.

    Ejemplo completo: una lista de piezas por zona¶

    Crea piezas.txt con estas cuatro líneas, sin cabecera:

    Azul;12
Gris;3
Azul;5
Ocre;10

    Para obtener solo las filas de la zona Azul puedes utilizar una condición sobre el primer campo, no una búsqueda de cualquier aparición de la palabra en la línea:

    awk -F';' '$1 == "Azul" {print $2}' piezas.txt

    La salida son dos líneas, 12 y 5. -F';' define el separador, $1 representa la zona y $2 la cantidad. El dólar de awk pertenece a su propio lenguaje; las comillas simples impiden que Bash intente expandirlo.

    Para sumar esas cantidades:

    awk -F';' '$1 == "Azul" {total += $2} END {print total + 0}' piezas.txt

    El resultado es 17. El bloque sin END se ejecuta en las filas que cumplen la condición; END se ejecuta al terminar. + 0 asegura una salida numérica cero aunque no hubiera coincidencias. Este ejemplo presupone cantidades válidas; si el archivo es externo, debes validar su formato antes de confiar en el cálculo.

    Texto literal, patrón de nombres y regex no son lo mismo¶

    grep -F 'a.b' busca exactamente los caracteres a.b. En una expresión regular, el punto sin escapar significa «un carácter cualquiera», por lo que un patrón a.b puede coincidir con acb. Para el punto literal en regex se escribe a\.b.

    En un patrón de nombres de la shell, *.log significa un nombre terminado en .log. El * no funciona igual que en una expresión regular: en regex repite el elemento anterior. Para no mezclar ambas ideas, anota siempre qué herramienta interpretará el patrón.

    find . -name '*.log' debe recibir el patrón, no una lista expandida antes por Bash. Por eso se entrecomilla. En cambio, [[ "$nombre" == *.log ]] utiliza deliberadamente un patrón dentro de la propia construcción de Bash.

    Cambiar texto no significa cambiar el archivo¶

    sed 's/antes/despues/' archivo imprime una versión transformada de cada línea. Sin una opción o una redirección de escritura, el archivo original permanece igual. El modificador g repite la sustitución en todas las coincidencias de cada línea; sin él solo se sustituye la primera.

    tr trabaja con caracteres: puede convertir minúsculas ASCII en mayúsculas o eliminar un delimitador. cut no interpreta un CSV general con comillas y separadores internos. Si el formato permite esos casos, necesitas un lector CSV que respete sus reglas.

    Al guardar el resultado de una transformación, utiliza una ruta de destino distinta de la entrada. Abrir con > un archivo antes de leerlo puede vaciarlo. Este error depende del mecanismo de redirección, no de que el filtro concreto sea grep, sort o sed.

    Problema explicado paso a paso: resumen de incidencias de un taller¶

    Crea un archivo de prueba taller.log:

    INFO|madera|llegada
ERROR|pintura|falta material
ERROR|madera|pieza rota
INFO|pintura|revisión
ERROR|pintura|ventilación

    contar errores por zona.

    grep '^ERROR|' taller.log | cut -d'|' -f2 | sort | uniq -c

    ¿Qué ocurre en cada tramo?¶

    1. grep conserva tres líneas que comienzan por ERROR|. En este patrón básico, | es un carácter literal.
    2. cut obtiene el segundo campo: pintura, madera, pintura.
    3. sort junta las dos apariciones de pintura.
    4. uniq -c cuenta cada grupo: un error de madera y dos de pintura. El orden y los espacios de presentación pueden depender de la configuración regional.

    Sin ordenar, las dos líneas de pintura no serían consecutivas y no formarían un único grupo.

    Para guardar el resumen sin borrar el log:

    grep '^ERROR|' taller.log | cut -d'|' -f2 | sort | uniq -c > resumen.txt

    resumen.txt es la salida. No utilices el mismo archivo como entrada y como destino de >: podría vaciarse antes de leerlo.

    Otras formas de preguntar sobre el mismo archivo¶

    awk -F'|' '$1 == "ERROR" {print $2 ": " $3}' taller.log
sed 's/^INFO|/AVISO|/' taller.log
wc -l < taller.log

    awk selecciona según el primer campo y muestra los otros dos. sed imprime una versión transformada, sin modificar el archivo porque no utiliza -i. wc devuelve 5 líneas si el archivo tiene el salto de línea final.

    ¿Patrón de nombre o expresión regular?¶

    find . -type f -name '*.log' busca nombres con un patrón de shell; las comillas evitan que la shell lo expanda antes. grep -E '^(ERROR|AVISO)\|' archivo utiliza una expresión regular extendida: la alternancia es | y la barra con \| busca el separador literal.

    Elemento de una expresión regular Lectura
    ^ / $ Inicio / final de línea
    [0-9] Una cifra
    . Un carácter cualquiera
    \. Un punto literal
    + con -E Una o más repeticiones

    Un patrón con cuatro grupos de una a tres cifras detecta la forma de una IPv4, pero no garantiza que cada octeto esté entre 0 y 255. No confundas reconocer una forma con validar todo su significado.

    Redirecciones: importa el orden¶

    Los descriptores 0, 1 y 2 corresponden a stdin, stdout y stderr. En programa > salida.log 2>&1, primero se conecta stdout al archivo y después stderr al mismo destino. Invertirlo (2>&1 > salida.log) puede dejar stderr apuntando al terminal.

    tee resumen.txt permite ver y guardar una salida; tee -a resumen.txt añade. Un here-document crea una entrada de varias líneas. Si entrecomillas el delimitador, no se expanden las variables:

    cat <<'FIN'
El texto $USER se conserva literalmente.
FIN

    Problema explicado paso a paso: buscar en archivos con espacios en el nombre¶

    Prepara una carpeta fichas con sala azul.txt, cuyo contenido sea material frágil, y sala gris.txt, con material normal.

    find fichas -type f -name '*.txt' -exec grep -HnF -- 'frágil' {} +

    Resultado esperado: una coincidencia en fichas/sala azul.txt:1:material frágil. find localiza archivos, -exec los pasa como argumentos y grep -HnF muestra nombre, línea y coincidencia literal. No se divide sala azul.txt en dos argumentos.

    Otra opción, con GNU xargs, es find fichas -type f -name '*.txt' -print0 | xargs -0 -r grep -HnF -- 'frágil'. El carácter nulo separa nombres de forma fiable y -r evita ejecutar grep sin archivos. La disponibilidad de -r depende de la implementación. No uses find ... | rm: rm necesita argumentos, no una lista por stdin.

    Necesitas buscar… Opción útil
    Sin distinguir mayúsculas grep -i
    Líneas que no coinciden grep -v
    Coincidencia silenciosa para un if grep -q
    Texto literal, sin regex grep -F
    Archivos sin bajar a subcarpetas find carpeta -maxdepth 1 -type f
    Archivos vacíos find carpeta -type f -empty

    Las opciones -size, -mtime y -user añaden criterios de tamaño, antigüedad y propietario. Revisa primero la selección con -print antes de asociarle una modificación.

    Ejercicios para practicar¶

    Intenta resolverlos antes de abrir la solución. Puedes consultar la teoría; después repite alguno sin mirar para comprobar qué recuerdas. Las pistas y soluciones están cerradas para que elijas cuándo verlas.

    1. Limpia una configuración de ejemplo¶

    Crea opciones.txt con estas líneas: # preferencias, vista=lista, una línea vacía y sonido=no. Obtén una salida que omita comentarios que empiezan en la primera columna y líneas vacías, sin modificar el archivo.

    Pista

    Usa una expresión regular que reconozca el principio de comentario o una línea sin contenido.

    Solución paso a paso 
    grep -Ev '^(#|$)' opciones.txt

    La salida contiene vista=lista y sonido=no. -E permite la alternativa y -v conserva lo que no coincide. Este enunciado no pide reconocer comentarios precedidos de espacios.

    2. Sustituye todas las marcas¶

    En pendiente pendiente listo, sustituye las dos apariciones de pendiente por hecho usando sed. Genera una salida, sin editar archivos. Explica qué pasaría si omites g.

    Pista

    La sustitución sin modificador afecta a la primera coincidencia de cada línea.

    Solución paso a paso 
    echo 'pendiente pendiente listo' | sed 's/pendiente/hecho/g'

    El resultado es hecho hecho listo. Sin g, sería hecho pendiente listo: solo cambiaría la primera aparición de la línea.

    3. Localiza documentos vacíos¶

    En una carpeta de prueba documentos, busca recursivamente solo archivos ordinarios vacíos cuyo nombre termine en .txt. Imprime sus rutas. No borres nada ni incluyas las carpetas vacías.

    Pista

    Combina nombre, tipo y tamaño vacío en find.

    Solución paso a paso 
    find documentos -type f -name '*.txt' -empty -print

    Las condiciones se combinan: debe ser archivo, terminar en .txt y estar vacío. Un .txt con texto, un .csv vacío y un directorio vacío quedan fuera. Las comillas dejan que find reciba el patrón sin expansión previa de la shell.

    UT1 · 5. Errores, depuración y scripts de administración¶

    El estado de un comando es información¶

    En shell, 0 indica éxito y otros valores indican otros resultados. grep devuelve 1 cuando no encuentra coincidencias: no siempre representa una avería. $? cambia con el siguiente comando; a menudo resulta más claro escribir if comando; then ....

    set -u detecta variables no definidas. set -e puede detener el script ante determinados fallos, pero tiene excepciones en condicionales y otras construcciones. set -o pipefail hace visible un fallo en una tubería que terminaría con un último comando correcto. Ninguna opción sustituye el tratamiento de los errores esperables.

    De un enunciado a una solución que puedas justificar¶

    Empieza escribiendo una llamada concreta y su salida. Si el programa recibe un archivo, decide si la ruta llega como argumento o se pregunta por teclado; son interfaces distintas. Después describe lo que debe ocurrir cuando falta la ruta, apunta a un directorio o no puede leerse.

    La solución no empieza por una colección de órdenes que conoces. Empieza por una secuencia con propósito: recibir la entrada, validarla, ejecutar una transformación, comprobar su resultado y presentar una respuesta. El mismo método sirve para una entrega y para un examen, porque permite explicar cada decisión.

    Prueba primero una transformación pequeña con datos que conozcas. Cuando funcione, conviértela en una función o intégrala en el programa. Añade el siguiente paso y repite. Si escribes todo de una vez, un fallo puede tener demasiadas causas posibles y te costará localizarlo.

    Qué comprueba cada nivel de revisión¶

    bash -n detecta problemas de estructura y sintaxis: un fi ausente o un bloque mal formado. No demuestra que la ruta exista ni que el cálculo sea correcto. bash -x sí ejecuta y muestra las expansiones: puede revelar un argumento vacío o una orden construida de forma distinta a la esperada.

    Un analizador como ShellCheck detecta muchos patrones problemáticos, como expansiones sin comillas. Tampoco conoce todo el significado del ejercicio. Finalmente, los casos de prueba comprueban comportamiento con datos concretos. Necesitas distinguir estos niveles para no dar por correcto un programa solo porque la sintaxis es válida.

    Durante la depuración, imprime el dato con límites visibles: echo "DEBUG: archivo=[$archivo]" >&2. Los corchetes ayudan a ver un dato vacío o espacios sobrantes. Retira o controla estos mensajes cuando dejen de hacer falta.

    Por qué set -e no reemplaza los if¶

    set -e tiene reglas y excepciones según el contexto de ejecución. Una orden usada como condición de un if, por ejemplo, puede fallar sin que eso signifique terminar inmediatamente el script: precisamente estás utilizando su resultado para decidir.

    Además, algunas órdenes devuelven un estado no cero como resultado normal de una consulta. Que grep no encuentre coincidencias puede ser una respuesta esperable. El programa debe decidir si significa «no hay resultados», «faltan datos obligatorios» o una situación que requiere terminar.

    Con una tubería, el estado habitual corresponde a la última orden. pipefail permite que un fallo anterior también afecte al resultado global. Aun así debes explicar qué harás cuando ese resultado sea no cero: mostrar una ayuda, continuar con otra entrada, reintentar o detenerte.

    Un registro útil cuenta qué ocurrió, no solo que algo falló¶

    Un mensaje como «error» no identifica la operación ni el dato que la provocó. «No se puede leer el archivo indicado: notas.txt» permite actuar. Mantén los resultados normales por stdout y los errores por stderr para que quien llame al programa pueda separarlos.

    No confundas el mensaje con el código de salida. Una orden puede imprimir algo y fallar; otra puede no imprimir nada y terminar correctamente. Si necesitas guardar el código en una variable, hazlo antes de ejecutar otra orden que sustituya $?.

    Preparar pruebas de examen y de consulta¶

    Para cada programa, combina un caso normal, un límite y al menos un error de entrada. Prueba también espacios en nombres si el programa trabaja con rutas. Escribe qué esperas antes de ejecutarlo: mirar una salida y decidir después que «parece bien» es una comprobación más débil.

    Una tabla de seguimiento muestra el estado de variables importantes después de cada paso. Si puedes reconstruirla a mano con datos pequeños, podrás explicar por qué funciona el script y detectar dónde diverge una ejecución real. Esa comprensión es lo que permite adaptar la técnica a un enunciado diferente, sin copiar una solución de clase.

    Problema explicado paso a paso: informe de líneas de un documento¶

    Recibir un archivo de texto y mostrar cuántas líneas tiene, incluido un nombre con espacios. No copia archivos ni crea usuarios.

    #!/bin/bash
set -u
if (( $# != 1 )); then
    echo 'Uso: bash informe.sh archivo' >&2
    exit 1
fi
archivo=$1
if [[ ! -f "$archivo" || ! -r "$archivo" ]]; then
    echo 'Se necesita un archivo ordinario que se pueda leer.' >&2
    exit 2
fi
if lineas=$(wc -l < "$archivo"); then
    echo "Documento: $archivo"
    echo "Líneas: $lineas"
else
    echo 'No se ha podido completar el recuento.' >&2
    exit 3
fi

    Prueba guiada¶

    Crea texto corto.txt con estas dos órdenes. La primera escribe la primera línea y la segunda añade la siguiente:

    echo "primera" > "texto corto.txt"
echo "segunda" >> "texto corto.txt"
    Llamada Resultado esperado
    bash informe.sh "texto corto.txt" 2 líneas; estado 0
    bash informe.sh ausente.txt Aviso de archivo; estado 2
    bash informe.sh Ayuda; estado 1

    wc -l cuenta saltos de línea. Un último fragmento sin salto final no aumenta el recuento. Esa diferencia puede explicar una aparente discrepancia con lo que ves en un editor.

    El segundo if contempla que el comando falle aunque se haya superado la comprobación previa: entre comprobar y leer, el estado del archivo podría cambiar.

    Cómo depurarlo¶

    bash -n informe.sh comprueba la sintaxis sin ejecutar el contenido. bash -x informe.sh "texto corto.txt" muestra los comandos expandidos mientras los ejecuta; evita utilizar trazas sobre secretos. Si tienes ShellCheck, shellcheck informe.sh ayuda a detectar problemas habituales.

    trap 'echo "Fin del laboratorio" >&2' EXIT ejecuta una acción al salir. También puedes capturar señales o ERR según el caso. Utiliza trap para limpieza y diagnóstico conscientes, no para ocultar un fallo.

    Aplicación a tareas de administración¶

    Un script de copias combina comprobación del origen, comando de archivado, estado y log. Un lector de CSV debe separar campos sin dividir los espacios, por ejemplo con while IFS=';' read -r nombre zona; do ...; done < datos.csv para un formato simple sin comillas internas. Un formato CSV general requiere un lector adecuado.

    En gestión de usuarios o servicios, separa consultar, decidir y modificar. Prueba primero la lógica con datos de laboratorio y mensajes de lo que haría. No necesitas ejecutar altas masivas para entender un if. Al interpretar un sondeo, recuerda también que una IP que no responde a ping no queda demostrada como libre: puede filtrar ICMP.

    Método de trabajo recuperado de los apuntes anteriores¶

    Antes de programar, escribe una llamada de ejemplo y su resultado esperado. Divide después el trabajo en leer, comprobar, transformar y presentar. Prueba cada parte por separado y añade las comprobaciones antes de conectarlas.

    Una función de error evita repetir mensajes y salidas en scripts más largos:

    #!/bin/bash
error() {
    echo "ERROR: $*" >&2
    exit 1
}
(( $# == 1 )) || error "Uso: bash revisar.sh archivo"
[[ -f "$1" ]] || error "No es un archivo ordinario: $1"
echo "Preparado para revisar: $1"

    Con un archivo existente, imprime la ruta. Sin argumento, termina con código 1 y una indicación de uso. La validación ocurre antes de leer $1 como dato de trabajo.

    Procesos, permisos y señales en el contexto de un script¶

    Un proceso es un programa en ejecución; su PID permite identificarlo. Una señal comunica un evento al proceso: SIGTERM solicita terminar y SIGKILL fuerza la terminación sin permitir limpieza. trap puede tratar determinadas señales, pero no SIGKILL.

    Los permisos r, w y x significan lectura, escritura y ejecución; en directorios, x permite atravesarlos. chmod u+x informe.sh añade ejecución al propietario. root es la cuenta administradora y sudo ejecuta una orden con la identidad autorizada por su configuración; no necesitas elevar permisos para practicar sobre tus propios archivos.

    Esto aporta contexto a Bash; el desarrollo completo de procesos, servicios y administración de directorio se incorporará cuando exista el material de esas unidades.

    Intenta resolverlos antes de abrir la solución. Puedes consultar la teoría; después repite alguno sin mirar para comprobar qué recuerdas. Las pistas y soluciones están cerradas para que elijas cuándo verlas.

    1. Revisa una dependencia antes de usarla¶

    Escribe un script que compruebe si wc está disponible. Si lo está, muestra Herramienta disponible; si no, escribe un error por stderr y termina con código 2. No instales nada desde el script.

    Pista

    command -v proporciona un estado que puede utilizar directamente el if.

    Solución paso a paso 
    #!/bin/bash
if command -v wc >/dev/null 2>&1; then
    echo 'Herramienta disponible'
else
    echo 'Falta la herramienta wc' >&2
    exit 2
fi

    Con wc disponible termina normalmente con estado cero. El otro camino informa por el canal de errores y utiliza un código que permite al programa que llama reconocer el fallo.

    2. Conserva el código de una operación¶

    Una comprobación falla y después haces echo 'Comprobado'. Al consultar $?, obtienes 0. Escribe una secuencia que guarde el estado de false antes del mensaje y muestre después ese estado guardado. No uses set -e en esta prueba.

    Pista

    Cada orden actualiza $?; la asignación debe hacerse inmediatamente después de la que interesa.

    Solución paso a paso 
    false
estado=$?
echo 'Comprobado'
echo "Estado de la prueba: $estado"

    El estado mostrado es 1. El echo intermedio no modifica la variable estado, aunque sí cambia el significado del $? que consultarías después.

    3. Organiza una investigación¶

    Un script debe procesar dos nombres con espacios, pero recibe cuatro palabras. Explica qué revisarías en la llamada, cómo comprobarías el número de argumentos y qué prueba repetirías después de corregirlo. No cambies el formato de los nombres para ocultar el error.

    Pista

    Distingue los datos de cómo la shell los separa antes de ejecutar el script.

    Solución paso a paso
    1. Revisaría si cada nombre completo está entre comillas al llamar al script.
    2. Observaría $# y recorrería "$@" con for argumento in "$@"; do echo "<$argumento>"; done.
    3. Repetiría la misma llamada con los nombres entrecomillados y comprobaría que hay exactamente dos argumentos completos.

    Cambiar nombres para quitarles espacios evita la prueba, pero no corrige el tratamiento de datos válidos con espacios.
